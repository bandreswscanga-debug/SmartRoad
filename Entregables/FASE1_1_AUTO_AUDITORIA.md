# SmartRoad S.O.S — Actividad de recuperación Sprint 1 — Fase 1.1 Auto-auditoría

## 1. ¿Qué pasó?

En el Sprint 1 no logramos entregar el proyecto completamente terminado porque nos quedó pendiente la parte de la base de datos. Durante la semana que teníamos para trabajar en el proyecto no hicimos un seguimiento suficiente de las tareas que faltaban y cuando llegó el momento de la entrega todavía no teníamos todo listo para complementar el proyecto.

El problema no fue solamente que faltara una parte del proyecto, sino que como equipo no nos organizamos bien para revisar con tiempo qué estaba terminado y qué faltaba. También debimos haber comprobado antes de la fecha de entrega que todos los integrantes tuvieran listas sus partes para poder unirlas y probar el proyecto completo.

## 2. Causa raíz

Después de revisar lo ocurrido, consideramos que la principal causa fue **la falta de organización y seguimiento durante la semana de trabajo**.

Teníamos el tiempo disponible para realizar la actividad, pero no establecimos un momento para revisar el avance general del proyecto. Por esta razón, la parte de la base de datos quedó pendiente hasta llegar muy cerca de la fecha de entrega.

Además, dependíamos de que uno de los integrantes tuviera lista esa parte para poder complementar el proyecto. El día de la entrega este integrante no pudo asistir, y como no habíamos dejado preparada una alternativa ni habíamos revisado antes el estado de la base de datos, no tuvimos suficiente tiempo para solucionar el problema.

Reconocemos que esto fue una responsabilidad del equipo en general, ya que debimos estar pendientes del avance de todas las partes y no esperar hasta el último momento para comprobar que el proyecto estuviera completo.

## 3. ¿Qué vamos a mejorar?

Para que no vuelva a pasar lo mismo, vamos a cambiar la forma en que estamos organizando el trabajo. Primero, vamos a poner fechas internas para terminar cada parte antes de la fecha oficial de entrega. También vamos a revisar periódicamente qué ha hecho cada integrante y qué tareas siguen pendientes.

Otra medida será mantener los avances importantes compartidos en el repositorio del proyecto. De esta manera, si algún integrante no puede asistir o tiene algún inconveniente, el resto del equipo podrá revisar su trabajo y continuar con lo necesario.

También vamos a intentar integrar y probar el proyecto antes de la fecha de entrega. Así tendremos tiempo para encontrar errores o partes que hagan falta y no esperar hasta el último día.

## 4. Matriz de riesgos

| Riesgo | Probabilidad | Impacto | ¿Cómo lo vamos a prevenir? |
| --- | --- | --- | --- |
| Que una parte del proyecto se retrase | Media | Alto | Revisar los avances durante la semana y no esperar al último día. |
| Que una tarea dependa de una sola persona | Media | Alto | Compartir los avances y mantener el trabajo en el repositorio. |
| No alcanzar a integrar todo el proyecto | Media | Alto | Integrar y probar el proyecto antes de la entrega. |
| Falta de comunicación entre integrantes | Media | Medio | Mantener comunicación y avisar cuando exista algún problema con una tarea. |
| Que se acumulen tareas para el último día | Media | Alto | Dividir el trabajo y establecer fechas internas para terminar cada parte. |
| Que un integrante no pueda asistir | Baja/Media | Alto | Tener los archivos y avances disponibles para que otro integrante pueda continuar. |

## 5. Compromiso con el MVP de diciembre

Sabemos que el retraso del Sprint 1 nos deja trabajo pendiente, por lo que no queremos que este problema se siga acumulando en los siguientes Sprint.

Para cumplir con el MVP en diciembre, vamos a trabajar con más anticipación, revisar los avances durante cada semana y tratar de tener las partes principales terminadas antes de las fechas oficiales. También vamos a realizar pruebas e integración con tiempo para poder corregir cualquier problema que aparezca.

El objetivo es aprender de lo ocurrido en este Sprint y mejorar la organización del equipo para que una situación similar no vuelva a afectar las siguientes entregas.
